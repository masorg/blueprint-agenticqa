The problem with letting a model review its own PR

Studies of a million+ real PRs show AI-agent review speeds up merges without clearly improving quality — and that review agents can be talked into approving vulnerable code by a persuasive PR description. The fix isn't less LLM. It's not letting the LLM be the last word.

The mechanism

The differentiator: it knows when the PR is itself an AI agent

Ordinary CI can't test agent behavior. Agentic QA routes on it — same pyramid, two extra layers, only when the change touches an agentic/LLM system.

Why this fits a Cloudera customer conversation

  • Single-process Cloudera CML/CAI Application — no new infra, installs once against an org's GitHub.
  • Language-agnostic behind a runner interface; ships Python/pytest today.
  • Any LLM the customer trusts — OpenAI, Cloudera AI Inference, Anthropic/Bedrock — swappable at runtime.
  • GitHub-native approval: a commit status and an /approve comment, write-access checked live. Nothing new to learn.
